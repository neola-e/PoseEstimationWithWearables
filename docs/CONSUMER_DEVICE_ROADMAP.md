# Next stage: iPhone and other IMUs

Planning snapshot: November 16, 2026. No native iPhone collector, Core ML export, or consumer-device benchmark has been implemented in this repository yet. The completed DIP studies provide a measured baseline for this next stage.

1. **Freeze the device input contract.** Keep the current network baseline and define sensor locations, model mask, units, world frame, sensor-to-body calibration, timestamps, 25 Hz resampling, and missing-data behavior. The model feature order is left wrist, right wrist, left pocket/thigh, right pocket/thigh, head: 15 acceleration values followed by 45 orientation values. Follow [IMU input format](IMU_INPUT_FORMAT.md); explicitly map device IDs rather than assuming the author's live transport order equals model order.
2. **Build an iPhone recorder and PC replay adapter.** Save raw sensor timestamps, acceleration, attitude, reference-frame metadata, calibration, and device placement. Preserve raw values before conversion. Validate gravity handling, acceleration scale, orientation convention, and mounting transforms against the existing input contract. Start with a supported mask that matches the available devices. The first milestone is deterministic replay through the existing Python network, with visible units and coordinate checks.
3. **Add synchronized multi-device capture.** Map each device's clock into one session timeline and measure drift, packet loss, reordering, and resampling effects. Record a repeatable action set: standing, turns, walking, arm motion, sitting, and pocket movement. Replay and live output should agree under the same timestamp and buffering policy.
4. **Measure live latency and causality.** Current rolling inference uses 125 frames of available history and emits the last frame. Existing centered five-frame acceleration smoothing uses two future samples, 80 ms at 25 Hz; filling/interpolation may add dependencies. Choose and report a buffering or causal-preprocessing policy, then evaluate its accuracy effect separately. Do not infer live latency from offline throughput.
5. **Compare refinements on device recordings.** Keep raw network, framewise IK, and Temporal IK as separate branches. Measure motion quality, jitter, failures, and compute cost before enabling a refinement by default. Without a reference motion-capture system, qualitative motion and jitter checks cannot establish pose accuracy.
6. **Port after replay is stable.** Prototype fixed-window neural inference conversion and check numerical parity on a Mac with the intended Core ML/iOS toolchain. Packed-sequence handling may require a deployment wrapper. The PyTorch autograd-based IK solvers need a separate implementation or deployment decision. Benchmark end-to-end latency, energy, memory, and thermal behavior on the actual devices before considering reduced precision.

Suggested first deliverable: one iPhone recording, its calibration metadata, and a PC replay command producing a pose stream in the documented format. Follow with the intended multi-device mask. Record each new experiment in [RESEARCH_LOG.md](RESEARCH_LOG.md), preserving the DIP and IK baselines.
